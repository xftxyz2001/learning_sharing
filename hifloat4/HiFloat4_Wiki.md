## 概述

**HiFloat4**（简称 **HiF4**）是一种创新的 4 位块浮点（Block Floating-Point, BFP）格式，专为深度学习推理和训练中的低精度计算而设计。该格式通过三级层次化缩放机制，在保持极低存储开销的同时，提供了优异的动态范围和量化精度。

### 核心优势

- **高存储效率**：平均每值仅需 **4.5 位**存储（32位元数据 + 64个4位元素）
- **宽动态范围**：组内动态范围达 **4.81 binades**
- **低量化误差**：相比 NVFP4 降低 24%，相比 MXFP4 降低 47%
- **硬件友好**：64长度点积运算面积仅为 NVFP4 的 **1/3**，功耗降低 **10%**
- **无需后训练缩放（PTS）**：避免了额外的软件开销和精度损失

## 格式结构

### 整体架构

HiF4 的基本单位由以下两部分组成：

```text
┌─────────────────────────────────────────────────────────┐
│                    HiF4 Unit (320 bits)                  │
├──────────────────────┬──────────────────────────────────┤
│  Scaling Metadata    │   In-Group Elements              │
│  (32 bits)           │   (64 × 4 bits = 256 bits)       │
├──────────────────────┼──────────────────────────────────┤
│ • E6M2 (8 bits)      │ • S1P2[1]  to S1P2[64]           │
│ • E1_8 (8 bits)      │                                  │
│ • E1_16 (16 bits)    │                                  │
└──────────────────────┴──────────────────────────────────┘
```

**关键参数：**

- **组大小（Group Size）**：64 个元素
- **总位数**：320 bits（32位元数据 + 256位数据）
- **平均每位元素**：320 / 64 = **5 bits**，但元数据分摊后为 **4.5 bits/element**

### 缩放元数据（Scaling Metadata）

HiF4 采用**三级层次化缩放结构**，从全局到局部逐级细化指数表示：

#### 第一级：E6M2 全局缩放因子

**E6M2** 是一种专门设计的无符号 8 位浮点格式，作为整个 HiF4 组的全局缩放基准。

**编码结构：**

| 字段 | 位数 | 说明 |
|------|------|------|
| 指数（Exponent） | 6 bits | 偏置值（Bias）= 48 |
| 尾数（Mantissa） | 2 bits | 隐藏整数位 = 1 |

**数值解释公式：**

$$X = 2^{E} \times 1.M$$

其中：

- $E$ 为无偏指数（unbiased exponent）
- $M$ 为 2 位尾数

**特殊值处理：**

- ✅ 支持 **NaN**（Not a Number）
- ❌ 不支持 Infinity（无穷大）
- ❌ 不支持 Zero（零）
- ❌ 不支持 Subnormal（非规约数）
- 仅支持**正常模式（Normal Mode）**

**设计目的：**

- 提供跨组的宽动态范围
- 将每组的峰值幅度归一化到后续层次结构的可表示上界
- 确保充分利用组内动态范围

#### 第二级：E1_8 微指数

**E1_8** 是 8 路 1 位微指数，用于扩展组内动态范围。

**特性：**

- **数量**：8 个微指数
- **每个微指数覆盖**：8 个连续的 S1P2 元素（64 ÷ 8 = 8）
- **编码方式**：
  - `1` → 缩放因子 $2^1 = 2$
  - `0` → 缩放因子 $2^0 = 1$

**层级关系：**

- 每个 E1_8 连接到两个相邻的第三级 E1_16 微指数

#### 第三级：E1_16 微指数

**E1_16** 是 16 路 1 位微指数，进一步细化局部指数差异。

**特性：**

- **数量**：16 个微指数
- **每个微指数覆盖**：4 个连续的 S1P2 元素（64 ÷ 16 = 4）
- **编码方式**：
  - `1` → 缩放因子 $2^1 = 2$
  - `0` → 缩放因子 $2^0 = 1$

**层级关系：**

- 每个 E1_16 直接连接到 4 个组内元素

### 元素编码（Element Encoding）

#### S1P2 符号幅度表示法

HiF4 使用 **S1P2** 格式编码 4 位组内元素。

**SXPY 记法说明：**

- **S**：符号位（Sign bit）
- **P**：二进制小数点位置
- **X**：整数部分位数（X-bit integer part）
- **Y**：小数部分位数（Y-bit fractional part）

**S1P2 结构：**

| 位位置 | 名称 | 说明 |
|--------|------|------|
| Bit 3 | Sign (S) | 符号位：0=正，1=负 |
| Bit 2 | Integer (I) | 1 位整数部分 |
| Bit 1-0 | Fraction (F) | 2 位小数部分 |

**可表示的值：**

| 二进制 | 十进制值 | 说明 |
|--------|----------|------|
| 0 1.11 | +1.75 | 最大正值 |
| 0 1.10 | +1.50 | |
| 0 1.01 | +1.25 | |
| 0 1.00 | +1.00 | |
| 0 0.11 | +0.75 | |
| 0 0.10 | +0.50 | |
| 0 0.01 | +0.25 | 最小正值 |
| 0 0.00 | +0.00 | 零 |
| 1 0.00 | -0.00 | 负零 |
| 1 0.01 | -0.25 | 最小负值 |
| ... | ... | |
| 1 1.11 | -1.75 | 最小负值（绝对值最大） |

**概念等价性：**

- S1P2 在数值上等价于浮点格式的 **E1M2**
- 但采用 S1P2 记法更直观易懂

## 数值表示

### 计算公式

对于 HiF4 组中的第 $i$ 个元素（$i \in [1, 64]$），其真实值 $V_i$ 的计算公式为：

**特殊情况：**

- 如果 $E6M2 = NaN$，则所有 $V_i = NaN$

**一般情况：**

$$
V_i = \mathrm{E6M2} \times
2^{\left(\mathrm{E1\_8}_{\lceil i/8 \rceil}
+ \mathrm{E1\_16}_{\lceil i/4 \rceil}\right)} \times \mathrm{S1P2}_i
$$

**索引映射关系：**

| 元素索引 $i$ | E1_8 索引 $\lceil i/8 \rceil$ | E1_16 索引 $\lceil i/4 \rceil$ |
|--------------|-------------------------------|--------------------------------|
| 1-8 | 1 | 1-2 |
| 9-16 | 2 | 3-4 |
| 17-24 | 3 | 5-6 |
| ... | ... | ... |
| 57-64 | 8 | 15-16 |

**示例计算：**

假设：

- $E6M2 = 2^{10} \times 1.5 = 1536$
- $\mathrm{E1\_8}_1 = 1$（对应元素 1-8）
- $\mathrm{E1\_16}_1 = 0$（对应元素 1-4）
- $\mathrm{S1P2}_1 = 1.25$

则：
$$V_1 = 1536 \times 2^{(1 + 0)} \times 1.25 = 1536 \times 2 \times 1.25 = 3840$$

### 动态范围分析

HiF4 的**组内动态范围**由蓝色部分决定（排除全局 E6M2 缩放）：

$$\mathrm{Dynamic\ Range} = \mathrm{E1\_8} + \mathrm{E1\_16} + \mathrm{S1P2}$$

**最大值计算：**

- $\mathrm{E1\_8} = 1$，$\mathrm{E1\_16} = 1$ → 缩放因子 $2^{(1+1)} = 4$
- $\mathrm{S1P2}_{\max} = 1.75$
- **最大正值**：$4 \times 1.75 = 7.0$

**最小值计算：**

- $\mathrm{E1\_8} = 0$，$\mathrm{E1\_16} = 0$ → 缩放因子 $2^{(0+0)} = 1$
- $\mathrm{S1P2}_{\text{min positive}} = 0.25$
- **最小正值**：$1 \times 0.25 = 0.25$

**动态范围（以 binades 计）：**

$$\log_2\left(\frac{7.0}{0.25}\right) = \log_2(28) \approx 4.81 \text{ binades}$$

> **binade** 是指浮点数中指数相同的连续数值区间。4.81 binades 意味着 HiF4 可以在组内覆盖约 5 个数量级的动态范围。

### 典型值对照表

| 特性 | HiF4 | NVFP4 |
|------|------|-------|
| 组大小 | 64 | 16 |
| 平均位数/元素 | 4.5 bits | 4.5 bits |
| 元数据位数 | 32 bits | 8 bits (E4M3) |
| 元素格式 | S1P2 (4 bits) | E2M1 (4 bits) |
| 组内动态范围 | 4.81 binades | 2.0 binades |
| 最大可表示值（归一化后） | 7.0 | 6.0 |
| 最小正值（归一化后） | 0.25 | 1.5 |
| 是否需要 PTS | ❌ 否 | ✅ 是 |

## 格式转换算法

### BF16 到 HiF4 的转换流程

将 64 个 BF16（Brain Floating Point 16-bit）数据转换为一个 HiF4 单元的完整算法如下：

**输入：** 64 长度的 BF16 向量 $V_{64}$

**输出：** HiF4 单元
$\{\mathrm{E6M2}, \mathrm{E1\_8}, \mathrm{E1\_16}, \mathrm{S1P2}_{64}\}$

### 三阶段转换详解

#### 第一阶段：三级树形归约（Lines 1-7）

此阶段通过并行比较找出各级局部峰值幅度。

##### 步骤 1.1：第一级归约（4→1）

```text
FOR i = 1 to 16:
    V16[i] = max(|V64[4×i-3 : 4×i]|)
```

- 将 64 个元素分为 16 组，每组 4 个
- 并行计算每组的最大绝对值
- 输出：16 个局部峰值 $V_{16}[1\ldots16]$

##### 步骤 1.2：第二级归约（2→1）

```text
FOR i = 1 to 8:
    V8[i] = max(V16[2×i-1 : 2×i])
```

- 将 16 个值两两配对
- 计算每对的最大值
- 输出：8 个局部峰值 $V_8[1\ldots8]$

##### 步骤 1.3：第三级归约（全局最大值）

```text
Vmax = max(V8)
```

- 从 8 个值中找出全局最大绝对值
- 输出：全局峰值 $V_{\max}$

**树形结构可视化：**

```text
Level 1:  64 BF16 values → 16 local maxima (4-to-1 reduction)
Level 2:  16 values      → 8 local maxima  (2-to-1 reduction)
Level 3:  8 values       → 1 global maximum
```

#### 第二阶段：层次化缩放元数据计算（Lines 8-14）

此阶段根据峰值计算三级缩放因子。

##### 步骤 2.1：计算高精度缩放因子

```text
SF_BF16 = Vmax × (1/7)_BF16
```

- 目标：将全局峰值归一化到 HiF4 组内可表示的最大值 7
- 除以 7 等价于乘以 $1/7$（避免除法性能损耗）

##### 步骤 2.2：量化为 E6M2（第一级缩放因子）

```text
E6M2 = BF16_to_E6M2(SF_BF16)
```

- 使用专用指令将 BF16 缩放因子量化为 E6M2 格式
- E6M2 作为全局基准缩放

##### 步骤 2.3：计算 E6M2 的倒数

```text
E6M2_REC = E6M2_REC_to_BF16(E6M2)
```

- bespoke 指令：直接从 E6M2 计算其在 BF16 中的倒数
- 避免显式除法操作
- **高效实现**：仅需 4 条目查找表（由 2 位尾数索引）+ 简单指数减法

##### 步骤 2.4：计算 E1_8（第二级微指数）

```text
E1_8[i] = (V8[i] × E6M2_REC ≥ 4) ? 1 : 0,  for i = 1 to 8
```

- 将 8 个局部峰值乘以 E6M2 的倒数
- 与阈值 4 比较（因为 E1_8 覆盖 8 个元素，需考虑后续 E1_16 的影响）
- 生成 8 个 1 位微指数
- **硬件优化**：可使用 fused multiply-compare 指令加速

##### 步骤 2.5：计算 E1_16（第三级微指数）

```text
FOR i = 1 to 16:
    E1_16[i] = (V16[i] × E6M2_REC × 2^(-E1_8[⌈i/2⌉]) ≥ 2) ? 1 : 0
```

- 将 16 个局部峰值依次乘以：
  1. E6M2 的倒数
  2. 对应的 E1_8 缩放因子（$2^{-E1\_8}$）
- 与阈值 2 比较
- 生成 16 个 1 位微指数
- **硬件优化**：
  - $2^{-E1}$ 只能是 0.5 或 1
  - 可使用乘法指令的特殊旁路模式快速计算 $BF16 \times 2^{-E1}$

#### 第三阶段：组内元素量化（Lines 15-18）

此阶段将原始 BF16 数据缩放并量化为 S1P2 格式。

##### 步骤 3.1：应用三级缩放因子

```text
FOR i = 1 to 64:
    V64_scaled[i] = V64[i] × E6M2_REC 
                    × 2^(-E1_8[⌈i/8⌉]) 
                    × 2^(-E1_16[⌈i/4⌉])
```

- 对每个原始 BF16 元素应用完整的三级缩放
- 得到归一化后的中间值

##### 步骤 3.2：量化为 S1P2

```text
S1P2_64 = BF16_to_S1P2(V64_scaled)
```

- 将缩放后的 BF16 值量化为 4 位 S1P2 格式
- **舍入策略**：
  - 推荐使用 **round-half-to-even**（银行家舍入）或
  - **round-half-away-from-zero**（远离零舍入）
- **溢出处理**：
  - 如果舍入后超出 S1P2 可表示范围
  - 钳位（clamp）到最近的可表示边界
  - 保持符号不变

### 硬件加速指令

为提高转换效率，建议实现以下专用指令：

| 指令名称 | 功能 | 优势 |
|---------|------|------|
| `BF16_to_E6M2` | BF16 到 E6M2 量化 | 避免通用转换开销 |
| `E6M2_REC_to_BF16` | E6M2 倒数转 BF16 | 4 条目 LUT + 指数减法，极快 |
| `Multiply-Compare` | 乘后立即比较 | 减少中间存储，提高吞吐 |
| `Multiply-Convert` | 乘后立即转换格式 | 融合操作，降低延迟 |
| `BF16 × 2^(-E1)` 旁路模式 | 快速乘以 0.5 或 1 | 避免完整乘法器 |

**舍入模式要求：**

- 所有 BF16 到 HiF4 的舍入操作必须使用：
  - ✅ Round-half-to-even（IEEE 754 默认）
  - ✅ Round-half-away-from-zero
- ❌ 禁止使用 truncate（截断）或 round-toward-zero

## 量化误差分析

### 实验设置

**数据集：**

- 18 个高精度随机矩阵
- 尺寸：$1024 \times 1024$
- 分布：高斯分布（Gaussian distribution）
- 均值：0
- 标准差：$\sigma = 0.01 \times 2^x$，其中 $x \in [0, 17]$

**对比格式：**

1. **HiF4**：使用上述转换算法
2. **MXFP4**：采用 Rouhani et al. (2023) 描述的方法
3. **NVFP4**：两种版本
   - **Direct Cast**：直接转换
   - **With PTS**：先使用 Post-Training Scaling 将张量峰值缩放到 2688，再转换为 NVFP4

**评估指标：**

- **均方误差（MSE）**：相对于原始高精度矩阵
- **归一化 MSE**：以 HiF4 为基准进行归一化

### 对比结果

**关键发现：**

1. **NVFP4 的动态范围不足问题**
   - 当数据值接近 NVFP4 的数值边界时
   - 发生溢出（overflow）和下溢（underflow）
   - 导致量化误差显著增加
   - **解决方案**：应用 PTS 可消除精度损失，但引入额外软件开销

2. **HiF4 和 MXFP4 的优势**
   - 无需 PTS
   - 无额外界限导致的量化开销
   - 在整个动态范围内保持稳定精度

3. **MSE 稳定性**
   - 排除 NVFP4 的波动后
   - 三种格式的 MSE 比值保持稳定

### 误差比例

**归一化 MSE 比值：**

$$\text{HiF4 : NVFP4 : MXFP4} = 1 : 1.32 : 1.89$$

**解读：**

- HiF4 的量化误差最低（基准 = 1）
- NVFP4 的误差比 HiF4 高 **32%**
- MXFP4 的误差比 HiF4 高 **89%**

**实际意义：**

- 虽然高斯分布匹配神经网络的集中特性
- 但实际场景中的量化误差可能有所不同
- 实验结果提供了定量参考，用于分析不同 4 位 BFP 格式的精度

**误差曲线特征：**

- HiF4：平稳低误差曲线
- NVFP4（无 PTS）：在极端值区域出现误差尖峰
- NVFP4（有 PTS）：误差降低但仍高于 HiF4
- MXFP4：始终高于 HiF4，但无明显波动

## 点积运算与硬件实现

### 64长度点积计算

对于两个 HiF4 单元 A 和 B 的点积运算：

**输入：**

- $A = \{\mathrm{E6M2}^{(A)}, \mathrm{E1\_8}^{(A)},
  \mathrm{E1\_16}^{(A)}, \mathrm{S1P2}_{64}^{(A)}\}$
- $B = \{\mathrm{E6M2}^{(B)}, \mathrm{E1\_8}^{(B)},
  \mathrm{E1\_16}^{(B)}, \mathrm{S1P2}_{64}^{(B)}\}$

**点积公式：**

$$
\begin{aligned}
\operatorname{Dot}(A, B)
&= \mathrm{E6M2}^{(A)} \times \mathrm{E6M2}^{(B)} \\
&\quad \times \sum_{i=1}^{8}
2^{\left(\mathrm{E1\_8}^{(A)}[i] + \mathrm{E1\_8}^{(B)}[i]\right)} \\
&\quad \times \sum_{j=2i-1}^{2i}
2^{\left(\mathrm{E1\_16}^{(A)}[j] + \mathrm{E1\_16}^{(B)}[j]\right)} \\
&\quad \times \sum_{k=4j-3}^{4j}
\left(\mathrm{S1P2}_{64}^{(A)}[k] \times \mathrm{S1P2}_{64}^{(B)}[k]\right)
\end{aligned}
$$

**计算层次：**

1. **最内层**：64 个 S1P2 元素对的乘积
2. **中间层 1**：每 4 个乘积求和，应用 E1_16 缩放
3. **中间层 2**：每 2 个结果求和，应用 E1_8 缩放
4. **最外层**：所有结果求和，应用 E6M2 全局缩放

### HiF4 vs NVFP4 计算流对比

#### HiF4 计算流（64 长度点积）

**特点：**

- **单对 HiF4 单元**即可满足 PE（Processing Element）输入宽度
- 组大小 = 64，完美匹配现代 Tensor Core / Cube Core 的 64 长度点积需求

**优化策略：**

1. **吸收 Level-3 微指数到 S1P2**
   - 在乘法前将 $E1\_16$ 应用到 S1P2 元素
   - S1P2（4 bits）→ **S2P2**（5 bits 整数）
   - 乘法器输入变为 5 位整数

2. **纯整数算术压缩**
   - 从 64 个乘积压缩到单个输出
   - 全程使用整数加法器和移位器
   - 仅在最后阶段需要：
     - 1 个小浮点乘法器（处理 E6M2）
     - 1 个大整数乘法器（最终累加）

**计算流程：**

```text
64 × (S2P2 × S2P2)  →  64 products (integer)
    ↓ (group by 4, apply E1_16 shifts)
16 × partial sums   →  16 intermediate results
    ↓ (pair up, apply E1_8 shifts)
8 × partial sums    →  8 intermediate results
    ↓ (accumulate all)
1 × final sum       →  apply E6M2 multiplication
    ↓
S12P4 output (FP32 accumulator)
```

#### NVFP4 计算流（64 长度点积）

**特点：**

- 需要 **4 对 NVFP4 单元**才能满足 64 长度点积
- 组大小 = 16，因此 4 × 16 = 64

**计算流程：**

```text
64 × (S3P1 × S3P1)  →  64 products (integer)
    ↓ (reduce within each group of 16)
4 × S10P2 outputs   →  4 partial results (still floating-point)
    ↓ (4 small FP multipliers for E4M3)
4 × scaled results  →  apply E4M3 scaling
    ↓ (4 large integer multipliers)
4 × final products  →  floating-point accumulation
    ↓
FP32 output
```

**关键差异：**

- 从 64 个乘积缩减到 4 个 S10P2 输出时保留整数运算
- 之后需要：
  - **4 个小浮点乘法器**（处理 E4M3 缩放）
  - **4 个大整数乘法器**（最终缩放）
- 最后的累加完全在浮点进行

### 硬件效率分析

#### 乘法器数量对比

| 阶段 | HiF4 | NVFP4 |
|------|------|-------|
| 元素乘法（64 次） | 64 × 5-bit 整数乘法器 | 64 × 5-bit 整数乘法器 |
| E1_16/E2M1 缩放 | 0（已吸收到元素） | 0（后续处理） |
| E1_8 缩放 | 0（移位操作） | 0（后续处理） |
| 中间缩放 | 0 | 4 × 小浮点乘法器 |
| 最终缩放 | 1 × 小浮点乘法器 + 1 × 大整数乘法器 | 4 × 大整数乘法器 |
| **额外乘法器总数** | **2** | **8** |

**结论：** HiF4 消除了 **6 个乘法器**

#### 面积和功耗估算

**假设条件：**

- 集成到现有的点积单元中（原本针对 FP16/BF16 和 INT8/Float8 优化）
- 高精度格式不需要累加树中的中间和最终乘法器
- E6M2 和 E4M3 等浮点元数据引入额外乘法器开销

**对比结果：**

| 指标 | HiF4 | NVFP4 | 改善 |
|------|------|-------|------|
| 增量面积 | ~1× | ~3× | **减少 67%** |
| 功耗 | ~1× | ~1.1× | **降低 10%** |
| 乘法器数量 | 2 | 8 | **减少 75%** |
| 累加复杂度 | 简单（整数为主） | 复杂（浮点为主） | **简化** |

**原因分析：**

1. **HiF4 的优势：**
   - 微指数（E1）通过移位实现，无需乘法器
   - 大部分累加过程使用整数算术
   - 仅在最后阶段需要少量浮点操作

2. **NVFP4 的劣势：**
   - E4M3 缩放需要浮点乘法器
   - 4 个部分结果需要独立缩放和累加
   - 浮点累加比整数累加更复杂、更耗电

**实际意义：**

- HiF4 使矩阵乘法的实现更加**面积高效**和**功耗高效**
- 特别适合大规模 AI 加速器中的密集矩阵运算
- 在相同芯片面积下可实现更高的吞吐量

## 应用场景

### 1. 深度学习推理

**适用场景：**

- LLM（大型语言模型）推理
- 计算机视觉模型部署
- 边缘设备上的实时推理

**优势：**

- 低存储带宽需求（4.5 bits/element）
- 高计算吞吐量（64 长度点积）
- 无需后处理缩放（简化部署流程）

### 2. 深度学习训练

**适用场景：**

- 混合精度训练中的梯度存储
- 激活值的低精度缓存
- 分布式训练中的通信压缩

**优势：**

- 保持训练精度（低量化误差）
- 减少通信带宽（相比 FP16/BF16）
- 硬件友好（易于集成到现有加速器）

### 3. AI 加速器设计

**适用场景：**

- GPU Tensor Cores 扩展
- NPU Cube Cores 优化
- 定制化 AI 芯片

**优势：**

- 面积效率高（相比 NVFP4 节省 67% 面积）
- 功耗低（降低 10%）
- 与现有 8-bit/16-bit 格式共享硬件资源

### 4. 高性能计算

**适用场景：**

- 大规模矩阵乘法
- 科学计算中的近似计算
- 数据压缩与传输

**优势：**

- 宽动态范围（4.81 binades）
- 稳定的量化精度
- 高效的点积实现

### D. 常见问题（FAQ）

**Q1: HiF4 为什么选择 64 作为组大小？**

A: 64 是现代 AI 加速器（如 Nvidia Tensor Cores 和 Ascend Cube Cores）支持的
64 长度点积的自然匹配。这使得单对 HiF4 单元即可满足 PE 输入宽度，最大化硬件利用率。

**Q2: HiF4 与 NVFP4 的主要区别是什么？**

A: 主要区别包括：

- 组大小：HiF4 为 64，NVFP4 为 16
- 动态范围：HiF4 为 4.81 binades，NVFP4 为 2.0 binades
- 硬件效率：HiF4 面积仅为 NVFP4 的 1/3
- PTS 需求：HiF4 无需 PTS，NVFP4 需要

**Q3: 为什么 HiF4 的量化误差更低？**

A: HiF4 通过三级层次化缩放（E6M2 + E1_8 + E1_16）提供了更宽的组内动态范围（4.81 binades），能够更好地适应数据分布，减少溢出和下溢。

**Q4: HiF4 是否支持 subnormal numbers？**

A: 不支持。E6M2 仅支持正常模式，这简化了硬件实现并提高了转换效率。

**Q5: 在实际应用中如何选择舍入模式？**

A:

- **Round-half-to-even**：符合 IEEE 754 标准，减少系统性偏差，推荐用于大多数场景
- **Round-half-away-from-zero**：在某些特定应用中可能更合适，例如金融计算
